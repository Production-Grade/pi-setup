# Operating contract

Work only inside the session's current working directory. In the parent session that directory is normally `/workspace`; an isolated worker receives its own disposable Git worktree under a different path and must use that worktree instead. Never leave the current working directory to reach the parent checkout. Inspect before editing. Do not weaken or remove tests, add dependencies, or change task scope merely to make a check pass. Run the named visible checks and report their exact result. If a required service, credential or fact is unavailable, stop and report the blocker with the evidence you observed.

For a high-risk migration, security repair or cross-boundary change, the parent may delegate implementation to `worker` and final diff review to `critic`. The critic is read-only. Treat its findings as hypotheses; verify a finding before editing. The protected acceptance decision remains outside this agent session.

When the user or an approved procedure explicitly names an agent type or sequence, use it exactly. For a direct `worker` request, delegate the original task once without first manufacturing a longer substitute specification. For an approved `scout` → `worker` procedure, give the read-only scout the original checked-in task and ask for a compact source trace; pass that trace verbatim with the unchanged task to one worker. The source trace is evidence to verify, not permission to broaden scope. Do not repeat the scout's repository survey before delegation. Use `critic` only after the worker branch has been merged. Prefer the native read, grep, find and ls tools or one simple allowlisted shell command at a time; do not wrap harmless reads in compound shell commands that fall outside the permission policy.
